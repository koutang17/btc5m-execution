# BTC/ETH 5m 预测市场马丁策略实现提示词

## 角色

你是一名量化交易系统实现工程师。请严格按照下面的规则实现一个可实盘运行的 Binance Predict 5分钟涨跌市场机器人。

不要自行增加、删除或改变策略规则。遇到规则未覆盖的情况，先提出确认，不要猜测。

## 目标市场

- 市场：Binance Predict 的 Crypto Up/Down 5分钟市场
- 标的：BTCUSDT 或 ETHUSDT，按账户配置选择
- 只使用已收盘的5分钟K线
- 不使用未收盘K线，不使用未来数据

## 核心信号

1. 取最近已收盘的5分钟K线。
2. 统计连续同向根数。
3. 当连续3根阳线时，下一根市场下注 DOWN。
4. 当连续3根阴线时，下一根市场下注 UP。
5. 十字星，即开盘价等于收盘价，视为无方向，会中断连续计数。
6. 信号出现后，必须等到下一根5分钟市场开盘再下单。

参数：

- MIN_STREAK：触发信号所需连续根数，默认3，可配置2到8
- ASSET：BTC 或 ETH，按账户配置

## 资金与马丁

参数：

- BASE_STAKE：首单金额，范围1到5 USDT
- MAX_LOSSES：最大亏损次数，范围1到12，默认5
- 档位金额：BASE_STAKE × 2^step
- step从0开始，对应第1档、第2档、第3档……

示例，首单1U、最大亏损5次：

    1 / 2 / 4 / 8 / 16

盈利后：

- 周期立即结束
- step归零
- 下一周期重新从首单金额开始

亏损后：

- step加1
- 下一根市场下注下一档，金额翻倍
- 如果step达到MAX_LOSSES，触发止损，周期结束，step归零

## 首单规则，重点

首单必须单独处理，不能使用未成交顺延。

首单未成交时：

1. 撤销该订单
2. 本周期立即取消
3. 记录为跳过周期，SKIP
4. 不进入第二单
5. 不把首单未成交视为亏损
6. 等待新的3连信号

原因：限价单未成交往往意味着价格已经朝有利方向移动；继续追下一根会形成逆向选择。

首单成交后：

- 正常持有到该5分钟市场结束并结算
- 盈利则周期结束
- 亏损则进入下一档

## 后续档位未成交规则

第2档及以后，允许有限次顺延。

参数：

- RETRY_COUNT：后续档位顺延次数，范围0到10，默认1
- 实际最大挂单次数 = 1 + RETRY_COUNT

未成交处理：

1. 同一档位第一次未成交，保留周期，下一根市场用CARRY_PRICE再挂一次。
2. 仍未成交，重复，直到达到最大挂单次数。
3. 同一档位最多挂1加RETRY_COUNT次。
4. 用完后周期结束。
5. 未成交本身不增加马丁档位，只有成交后发生亏损才增加。

顺延价格：

- PRICE：首单或初始限价，例如0.40或0.46
- CARRY_PRICE：后续顺延限价，例如0.45或0.48
- CARRY_PRICE必须大于等于PRICE，否则逻辑不成立

## 结算与胜负判定

订单成交后，等待该5分钟市场结束。

建议等待市场结束后至少2秒，再查询持仓结算。

判定优先级必须严格如下：

1. 如果接口明确返回 WIN，判定为赢。
2. 如果接口明确返回 LOSS，判定为输。
3. 如果接口返回isWinner为布尔值，按它判断。
4. 如果result为空或isWinner缺失，按实际盈亏pnl判断：
   - pnl大于0：赢
   - pnl小于0：输
   - pnl等于0：检查canClaim，否则按输处理

绝对禁止：

    result为空时直接默认为输

这是必须覆盖的回归测试点。

周期结算：

- 最终订单赢：周期结束，记WIN
- 最终订单输且未到MAX_LOSSES：进入下一档
- 最终订单输且达到MAX_LOSSES：周期止损结束，记STOP
- 如果最终订单赢，但前期亏损更大，周期净盈亏可能仍为负；必须如实记录实际pnl，但结果仍为WIN，不能改写为STOP

## 周期状态定义

每个周期只能处于以下之一：

- WIN：最终订单盈利结束
- SKIP：首单未成交，周期取消
- STOP：达到最大亏损，或后续档位顺延耗尽且已有实际亏损
- ACTIVE：当前正在等待或持仓

统计必须分别记录：

- 盈利周期数
- 跳过周期数
- 止损周期数
- 总周期数

统计总数必须等于三类之和，不能出现负数或重复计数。

## 止损后冷却

当周期因为达到 MAX_LOSSES 触发止损后：

- 设置冷却到下一个5分钟边界
- 如果同一根K线收盘时又出现新信号，不立即开新周期
- 至少跳过当前这一根5分钟市场
- 下一个5分钟边界再重新判断信号
- 冷却只针对连败止损，不适用于首单跳过

## 6连风控

在每次准备下新单前检查最近6根已收盘K线。

触发条件：

- 最近6根全部同向
- 且这6根的累计涨跌幅绝对值大于1.4%

触发后：

- 已有挂单保留
- 下一单禁止
- 当前马丁周期重置
- 发送风险提醒

6连条件解除后，允许新周期。

## 硬止损

参数：

- HARD_STOP_MODE：none、drawdown、loss_cycles
- HARD_STOP_DRAWDOWN：最大回撤，单位U
- HARD_STOP_LOSS_CYCLES：最大连续亏损周期数

触发条件：

- drawdown模式：策略累计收益从历史峰值回撤达到阈值
- loss_cycles模式：连续亏损周期数达到阈值

触发后：

- 立即暂停开新单
- 写入PAUSE状态
- 发送企业微信告警
- 不自动恢复，必须人工确认

## 资产切换

- 每个账户独立配置ASSET
- 当前周期运行中切换资产，不改变当前周期
- 下一周期生效
- 切换后K线、市场筛选、下单、通知都必须使用新资产
- 不允许同一账户同一时间同时交易BTC和ETH

## 下单执行顺序

每根5分钟市场：

1. 等待上一根收盘
2. 获取已收盘K线
3. 计算信号
4. 如果当前周期已有持仓或挂单，先处理结算和顺延
5. 没有活动周期且存在新信号时，开新周期
6. 确定方向和档位金额
7. 查询目标5分钟市场，必须匹配：
   - symbol等于ASSET加USDT
   - timeframe等于5 min
   - tradingStatus等于OPEN
   - startDate匹配目标轮次
8. 获取UP/DOWN token
9. 查询盘口ask
10. 按PRICE或CARRY_PRICE挂限价单
11. 等待成交或轮次结束
12. 成交后等待结算
13. 更新状态、记录、通知

## 状态与安全要求

- 每个账户独立状态文件
- 每笔订单必须保存orderId，防止重复下单
- 重启后先恢复未结算订单，不能直接开新单
- 同一账户只允许一个机器人实例
- 写入状态必须原子化，避免半写文件
- 下单前检查账户是否CONNECTED
- 网络错误不能直接判定登录失效
- 登录失效只能由明确的认证错误或UNCONNECTED触发
- 查询余额失败时，先区分网络错误和认证错误

## 通知和记录

每次订单、成交、结算、跳过、止损、硬止损都要记录：

- 时间
- 账户
- 资产
- 周期号
- 档位
- 金额
- 方向
- 限价
- 成交价
- 成交份数
- 盈亏
- 结果

企业微信通知必须保留原始信息，只对状态词标红，例如：

    已挂单，等成交
    已成交
    未成交
    已撤单
    跳过
    赢
    输
    止损

不要标红成交价、成交份数、金额中的成交二字。

## 必须通过的验收测试

1. 首单未成交：
   - 不允许下第二单
   - 记为SKIP
   - 不增加连续亏损

2. 首单盈利：
   - 周期立即结束
   - 不允许下第二单
   - 记为WIN

3. 首单亏损后第二单：
   - 下一根市场下单
   - 金额为首单2倍

4. result为空但pnl大于0：
   - 必须判赢
   - 周期结束
   - 不允许继续下一档

5. result为空但pnl小于0：
   - 判输
   - 进入下一档

6. 最大亏损次数为5：
   - 第5次亏损后止损
   - 不允许第6单

7. 后续档位未成交：
   - 按RETRY_COUNT重复
   - 用完结束周期
   - 不增加马丁档位

8. 6连风控：
   - 下一单被阻止
   - 当前周期重置
   - 已有挂单不受影响

9. 十字星：
   - 中断连续计数
   - 不产生信号

10. 重启恢复：
    - 不重复下单
    - 能找到已成交未结算订单
